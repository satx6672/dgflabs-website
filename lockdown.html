Built in Response to the October 30 Chrome Web Store .crx Scraping Wave

Since October 30, 2026, a store-wide wave of automated scripts has been pulling Chrome extension .crx packages directly from Google’s update servers—showing up in developer dashboards as unexplained daily spikes of 20–30+ installs from Romania under OS: Other with flat Weekly Users. Many developers either haven’t noticed or write it off as harmless analytics noise, missing the real exposure: every downloaded .crx unpacks into plain-text JavaScript, leaving hardcoded API keys, Bearer tokens, and backend endpoints in background.js readable within hours of release. Once a static key leaks, you are trapped in reactive damage control—scrambling to rotate or revoke exposed credentials while risking breaking every legitimate user’s live extension.

You cannot stop bots from downloading your .crx off Google’s servers, and most MV3 boilerplates stop at the UI—leaving your API unprotected and client-side chrome.storage.local paywalls trivial to bypass in DevTools. Worse, loading external billing scripts violates Manifest V3’s strict ban on remotely hosted code, while third-party payment wrappers take an ongoing cut of your revenue without securing your backend. The MV3 Lockdown Kit neutralizes extracted keys at the server boundary—pairing explicit chrome-extension:// CORS pinning, a registered installation_uuid gate, and rotating 4-hour tokens so any scraped key is rejected with a 403 in milliseconds.

What’s Under the Hood

4-Layer .crx Anti-Scraping Lockdown

Even if an attacker unpacks your .crx and extracts your Bearer API key, backend requests are blocked (HTTP 403) unless accompanied by a registered installation_uuid and a live, rotating 4-hour continuity_ref session token (±15 min stealth jitter) behind explicit chrome-extension:// CORS origin pinning.

Direct-Stripe Webhook & Multi-Product Engine

Cryptographically verified Stripe checkout.session.completed webhook handler backed by PostgreSQL (middleware_licenses). Supports single or multiple extensions on one shared backend via product_id isolation—zero ExtensionPay or third-party wrapper fees.

MV3-Compliant Service Worker Bridge

Lightweight, non-blocking background.js module with a race-condition-proof UUID generator, automatic 4-hour token rollover (chrome.alarms), automatic HTTP 410 token refresh on protected calls, and direct Stripe client_reference_id checkout handoff—zero remote code execution.

Deploy-Ready FastAPI + Async SQLAlchemy

Production-tested on Render + PostgreSQL with automatic table initialization, an async connection pool, a built-in local SQLite fallback for instant local testing, environment-gated debug routes (DGF_DEBUG), and a step-by-step setup guide.
